# Pages

App routes generated by `/design-app` Phase 0. All pages live in `charm-email-os/app/` and consume components from [[../components/index]]. Mock data lives at `charm-email-os/lib/mock/charm.ts` and will be replaced with real fetches once [[../../architecture/agent-runtime]] Phase 2 lands.

## Layout

| Route | File | Purpose |
|-------|------|---------|
| Root layout | `app/layout.tsx` | HTML/body shell, font config (Fraunces + Manrope + Geist Mono), `<AppShell />` wrapper |
| Workspace shell | `app/workspaces/[id]/layout.tsx` | Workspace header (name + slug + StatusPill + ContextFreshnessPill) + 12-item sub-nav left rail |

**AppShell** (`components/charm/app-shell.tsx`) is a client component that reads `usePathname()` and renders `VillageSidebar` for redesign routes or the legacy `Sidebar` for everything else — lets the redesign coexist with legacy `/clients/*`, `/reports/*`, `/infrastructure/*` routes.

## Legacy Routes (preserved, untouched)

These continue to work and render with the legacy sidebar via `AppShell`'s path-based switch:

- `/clients/*` — legacy client detail views
- `/reports/*` — the 7-page operator queue (cancel-candidates, capacity, disconnects, incubation-stuck, kills, quarantined, rotation)
- `/infrastructure/*` — legacy infra views
- `/api/*` — backend API routes

## State Handling

All built pages handle:
- **Empty state** — dashed-border panel with icon + message
- **Populated state** — rendered with mock data
- **Loading state** — not separately rendered (server components fetch at render time)
- **Error state** — `notFound()` for missing workspace IDs

Once the backend lands, swap `getWorkspace(id)` and friends to real `await fetch(...)` calls and add proper loading skeletons via [[../components/index]] (shadcn `Skeleton` is available).
