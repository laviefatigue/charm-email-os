# Strategy Suggestions

AI-generated campaign sequences stored for human review and approval.

## Overview

Strategy suggestions are 4-email campaign sequences generated by the [[strategy-ai-container]]. Each suggestion represents a complete campaign with subject lines, email bodies, and metadata for a specific angle (custom_signal, persona_pain, case_study, risk_efficiency).

```
Strategy Generation Job
    ↓ AI generates 4 campaigns
Strategy Suggestions (pending)
    ↓ Human reviews
Approved / Denied / Revision Requested
    ↓ If approved
Push to EmailBison via spintax
```

## Database Schema

### strategy_suggestions table

```sql
CREATE TABLE strategy_suggestions (
    id UUID PRIMARY KEY,
    job_id UUID REFERENCES strategy_generation_jobs(id),
    client_id UUID REFERENCES clients(id),

    -- Email content
    variant_number INTEGER,           -- 1, 2, 3, or 4
    subject_line TEXT,
    email_body TEXT,

    -- Metadata from skill
    score INTEGER,                    -- 0-100 QA score
    rationale TEXT,
    used_variables JSONB,             -- ["{{first_name}}", "{{company_name}}"]
    missing_variables JSONB,
    campaign_type VARCHAR(50),        -- custom_signal, persona_pain, case_study, risk_efficiency

    -- Review status
    status VARCHAR(50) DEFAULT 'pending',  -- pending, approved, denied, revision_requested
    human_comment TEXT,
    reviewed_by VARCHAR(255),
    reviewed_at TIMESTAMP,

    -- Cycle linkage (see [[strategy-cycles]])
    cycle_id UUID REFERENCES campaign_cycles(id),
    lineage_id UUID,                  -- Groups versions across cycles
    campaign_version INTEGER DEFAULT 1,

    -- Soft delete
    is_active BOOLEAN DEFAULT true,

    generation_round INTEGER DEFAULT 1,
    created_at TIMESTAMP
);
```

## Approval Workflow

### Status Flow

```
pending → approved    (human approves)
pending → denied      (human rejects)
pending → revision_requested (human wants changes)
```

### API Endpoint

**PATCH `/api/strategy/sequences/{sequence_id}`**

```typescript
interface SequenceReviewRequest {
    action: 'approve' | 'deny' | 'revision';
    comment?: string;
    reviewer?: string;
}
```

**Backend Handler** (`api/routes/strategy.py:update_sequence_status`):

```python
@router.patch("/sequences/{sequence_id}")
async def update_sequence_status(sequence_id: UUID, request: SequenceReviewRequest):
    # Map action to status
    status_map = {
        'approve': 'approved',
        'deny': 'denied',
        'revision': 'revision_requested'
    }
    new_status = status_map.get(request.action, request.action)

    # Update database
    await execute("""
        UPDATE strategy_suggestions
        SET status = $1, human_comment = $2, reviewed_by = $3, reviewed_at = NOW()
        WHERE id = $4
    """, new_status, request.comment, request.reviewer, sequence_id)
```

## Database Triggers Issue

### The Problem

A database trigger was manually added to `strategy_suggestions` that referenced a non-existent `is_active` column. This caused approval updates to fail:

```
asyncpg.exceptions.UndefinedColumnError: column "is_active" does not exist
```

The UPDATE query doesn't reference `is_active`, but PostgreSQL triggers fire on any UPDATE and can reference any column via `NEW.*` or `OLD.*`.

### The Fix

On API startup, `database.py` now:

1. **Drops any user-defined triggers** on `strategy_suggestions`
2. **Adds the `is_active` column** if missing

```python
# Drop problematic triggers
triggers = await fetch("""
    SELECT tgname FROM pg_trigger
    WHERE tgrelid = 'strategy_suggestions'::regclass
    AND NOT tgisinternal
""")
for trigger in triggers:
    await execute(f'DROP TRIGGER IF EXISTS "{trigger["tgname"]}" ON strategy_suggestions')

# Add column
await execute("""
    ALTER TABLE strategy_suggestions
    ADD COLUMN IF NOT EXISTS is_active BOOLEAN DEFAULT true
""")
```

### Prevention

- Never add database triggers manually without code-level documentation
- All schema changes should go through migration files
- Triggers should be versioned and tracked in `migrations/`

## API Endpoints

```typescript
// Get sequences for a client
GET /api/strategy/sequences/{client_id}
    ?sort=created_at&order=desc
    &status=pending|approved|denied
    &strategy_id=uuid

// Get single sequence
GET /api/strategy/sequences/{client_id}/{sequence_id}

// Update sequence status
PATCH /api/strategy/sequences/{sequence_id}
    body: { action: 'approve'|'deny'|'revision', comment?: string }

// Edit sequence content
PATCH /api/strategy/sequences/{sequence_id}/edit
    body: { subject_line?: string, email_body?: string, emails?: EmailEdit[] }

// Request revision
POST /api/strategy/sequences/{sequence_id}/revision
    body: { instruction: string }
```
